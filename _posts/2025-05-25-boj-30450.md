## 문제 링크

[BOJ 30450](https://www.acmicpc.net/problem/30450)


## 난이도

음... {% include solved_tier.html code="D5" %}에서 대충 {% include solved_tier.html code="D4" %}정도?


## 시간복잡도

- \$$ \mathcal{O}(kc) $$


## 알고리즘

- Ad-hoc
- Constructive


## 풀이

정답이 되는 문자열을 $f(c, S)$ 라고 하자 ($S$ 는 길이 $k$의 입력 문자열). 함수 $f$는 점화식처럼 생각해서 계산할 수 있다.

예시로, $c = 4, S = \text{"42311"}$ 라고 하자. 그렇다면 $4$ 가 등장한 이후 $ \text{"2311"}$이 문자열에 등장하지 않아야 하므로, 정답 문자열의 끝부분에 $f(4,  \text{"2311"})$과 같은 형태가 필요하다고 직관적으로 생각해볼 수 있다. 즉 정답 문자열은 $\text{"1234"} + f(4,  \text{"2311"}) $ 같은 형태일 것이다.

그런데 $4 + f(4,  \text{"2311"})$ 는 $ \text{"12311"},  \text{"22311"},  \text{"32311"}$ 같은 문자열들이 표현이 되지 않으므로, 

<div class="my-spacer-2"></div>

증명 없이 Proof By AC 했는데, 아마 귀납적으로 증명이 가능할 것 같다. (근데 쉽진 않을 것 같다)


## 전체 코드

```c++
#include <bits/stdc++.h>
using namespace std;

int a[10010];
int main(){
    ios_base::sync_with_stdio(false);cin.tie(nullptr);
    int k,c;
    cin>>k>>c;
    for(int i=1;i<=k;i++)cin>>a[i];

    for(int i=1;i<=k;i++){
        for(int j=1;j<=c;j++){
            if(a[i]!=j) cout<<j<<" ";
        }

        if(i+1<=k){
            cout<<a[i+1]<<" ";
            if(a[i]!=a[i+1])cout<<a[i]<<" ";
        }
    }
    return 0;
}
```


## 기타

분명 코드는 출력 말고 하는 일이 거의 없는데, 출력해야 하는 정수가 2500만개나 돼서 시간제한인 2초를 거의 꽉 채운다... (보통 입출력이 같은 $\mathcal{O}(1)$ 연산 중에 가장 느리기 때문에, 대부분의 문제가 입출력해야 하는 정수 개수가 500만개 이하인 경우가 많다)
