## 문제 링크

[BOJ 30450](https://www.acmicpc.net/problem/30450)


## 난이도

{% include solved_tier.html code="D5" %} ~ {% include solved_tier.html code="D4" %}


## 시간복잡도

- \$$ \mathcal{O}(kc) $$


## 알고리즘

- Ad-hoc
- Constructive


## 풀이

정답이 되는 문자열을 $f(c, S)$ 라고 하자 ($S$ 는 길이 $k$의 입력 문자열). 함수 $f$를 점화식처럼 생각해 볼 수 있다.

예시로, $c = 4, S = \text{"42311"}$ 라고 하자. 그렇다면 $4$ 가 등장한 이후 $ \text{"2311"}$이 문자열에 등장하지 않아야 하므로, 정답 문자열의 끝부분에 $f(4,  \text{"2311"})$과 같은 형태가 필요하다고 직관적으로 생각해볼 수 있다. 즉 정답 문자열은 $\text{"1234"} + f(4, \text{"2311"})$ 같은 형태일 것이다.

그런데 이렇게 만들면 $\text{"12311"}, \text{"22311"}, \text{"32311"}$ 같은 문자열들이 부분 수열에 없으므로, 이것까지 표현이 가능하도록 문자를 조금 더 추가해줘야 한다. $\text{"311"}$은 이미 $f(4, \text{"2311"})$에 부분 수열로 있으니, $f(4, \text{"42311"}) = \text{"12324"} + f(4, \text{"2311"})$로 구성하게 되면 $\text{"42311"}$을 제외한 모든 부분 수열을 가진 문자열이 완성된다.

이 점화식의 논리를 바탕으로, 각 $S_i$에 대해 추가되는 문자열을 아래 코드처럼 계산하여 붙여가면 정답 문자열이 완성된다.

<div class="my-spacer-2"></div>

증명 없이 Proof By AC 했는데, 아마 귀납적으로 증명이 가능할 것 같다. (쉽진 않을 것 같다)


## 전체 코드

```c++
#include <bits/stdc++.h>
using namespace std;

int a[10010];
int main(){
    ios_base::sync_with_stdio(false);cin.tie(nullptr);
    int k,c;
    cin>>k>>c;
    for(int i=1;i<=k;i++)cin>>a[i];

    for(int i=1;i<=k;i++){
        for(int j=1;j<=c;j++){
            if(a[i]!=j) cout<<j<<" ";
        }

        if(i+1<=k){
            cout<<a[i+1]<<" ";
            if(a[i]!=a[i+1])cout<<a[i]<<" ";
        }
    }
    return 0;
}
```


## 기타

분명 코드는 출력 말고 하는 일이 거의 없는데, 출력해야 하는 정수가 2500만개나 돼서 시간제한인 2초를 거의 꽉 채운다... (보통 입출력이 같은 $\mathcal{O}(1)$ 연산 중에 가장 느리기 때문에, 대부분의 문제가 입출력해야 하는 정수 개수가 500만개 이하인 경우가 많다)

아무래도 이 코드처럼 출력만 하는 코드가 의도된 풀이로 보인다.


채점환경에 따라 입출력이 느린 환경인 경우 FastIO가 필요할 수도 있어 보인다.
